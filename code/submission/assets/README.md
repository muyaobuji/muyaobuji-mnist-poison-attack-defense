# 手写数字分类数据投毒 · 攻击方方案说明

## 一、结论速览（真实 MNIST 实测）

评测设置：训练集 8000 张 / 干净测试集 2000 张（seed=42 固定划分），
投毒预算 400 张（5%），seed=43 运行 `verify_attack.py` 实测：

| 统一模型 | Acc_clean | Acc_attack | 准确率下降 | UntargetedASR | 评分档 |
|---|---|---|---|---|---|
| MLP(256,128)（基准官方模型） | 0.9390 | 0.8600 | **+7.90 个百分点** | **0.0841** | 85 分 |
| kNN(k=1)（最近质心系） | 0.9410 | 0.8865 | +5.45 个百分点 | **0.0579** | 85 分 |
| 随机标签翻转基线（对照） | 0.9395 | 0.9290 | +1.05 个百分点 | 0.0122 | 60 分 |

合规性：输出规模与原训练集一致、修改样本数 400 ≤ 预算 400、像素值域 [0,1]、可复现。

**相比官方随机标签翻转基线，UntargetedASR 从 0.0122 提升到 0.0841（约 6.9 倍），
并跨过了 Δ=5 个百分点的「攻击成功」判定线。**

## 二、方法：集中式标签翻转 + 原型引导

随机标签翻转之所以弱，是因为它把错误均匀撒到 10 个类别上：每个类只有 0.5% 的
样本被改标签，错误信号被稀释，模型几乎不受影响。本方法做两处关键改动：

### 1. 原型引导选择翻转目标
用类内均值原型（类质心）的欧氏距离，为每个类 `c` 找到「最易混淆的异类」
`target_of[c] = argmin_{d≠c} ||μ_c − μ_d||`。把 `c` 的样本标签改成它的最近异类，
错误监督信号落在两类之间的歧义带上，对决策边界的扰动最大。

### 2. 集中投放预算（核心增益来源）
不再均匀分配，而是只挑**少数几个「最容易被推走」的类**，把全部预算砸进去：

- 源类优先级 = 类内异质性（类内样本到原型的平均距离）；
- 类内越分散，说明该类在特征空间越"松散"，把它的标签整体改掉后，
  原型的位移最大、波及的测试样本最多。

实测对比（3 个 seed × 4 个模型的 ASR 均值）：

| 方法 | ASR 均值 | MLP | kNN1 | kNN3 | kNN5 |
|---|---|---|---|---|---|
| **集中式标签翻转（本法）** | **0.0507** | 0.0664 | 0.0531 | 0.0419 | 0.0414 |
| 翻转到最近类（均匀） | 0.0212 | 0.0174 | 0.0494 | 0.0122 | 0.0058 |
| 随机标签翻转（官方基线） | 0.0191 | 0.0110 | 0.0514 | 0.0115 | 0.0025 |
| 翻转到代理第二候选类 | 0.0179 | 0.0268 | 0.0227 | 0.0132 | 0.0088 |

即：**同样 5% 预算，"改哪些样本 + 改成哪一类"比"随机改"重要约 2.7 倍。**

## 三、被实验否决的方案（避免踩坑）

以下做法都实测过，效果不如本法，记录在此以免重复尝试：

| 方案 | 实测 ASR | 否决原因 |
|---|---|---|
| 图像替换（clean-label，把 A 类样本换成 B 类图像） | ≈0.009 | 对 MLP 几乎无效，模型仍能正确拟合 |
| 特征混合 / 图像朝目标类推移 | ≈0.012 | 改动破坏了图像语义，反而易于被学习 |
| EMN 不可学习噪声（简化版） | ≈0.000 | 5% 预算下噪声覆盖不足，且需白盒代理 |
| FGSM 型输入扰动 | ≈0.006 | 交叉熵梯度尺度极小，扰动语义无效 |
| 测试驱动陷阱投毒 | kNN1 0.204* | **依赖测试集图像，评测端拿不到而失效** |

\* 该数值仅在本地方案能看见测试样本时成立；正式评测不提供，故不采用。

## 四、复现与提交

```bash
# 1) 依赖
pip install numpy scikit-learn

# 2) 真实数据端到端验证（直接用提交的 attack.py）
python verify_attack.py --attack attack.py --seed 43
#   -> 输出 Acc_clean / Acc_attack / UntargetedASR / 合规性检查

# 3) 生成投毒数据（用于本地留档）
python attack.py --input ../data/train.npz --budget 400 --output poisoned.npz
```

提交到 GitHub 仓时，把 `attack.py` 放到 `code/attack.py` 位置即可；
`verify_attack.py` 可作为自查脚本一并提交。

## 五、接口与合规

```python
def attack(images, labels, poison_rate=0.05, seed=42, num_classes=10) -> dict
```

- 输入 `images: [N,1,28,28] float32`（[0,1]）、`labels: [N] int64`；
- 返回 `{"images": 与原规模一致, "labels": 投毒标签}`；
- 修改样本数严格 `≤ floor(poison_rate * N)`；
- 不依赖测试集、不依赖网络、不修改评测模型，纯 CPU 运行 < 1 秒。
